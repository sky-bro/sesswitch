## 职责边界

**提供方（providers）** 负责发现和规范化会话，**宿主（hosts）** 负责验证并定位运行中的界面，**启动器（launchers）** 负责显示模型，并通过 CLI 委托执行操作。提供方不能直接激活窗口；启动器不能直接读取本地记录或提供方文件。包的位置见[开发指南](development.md#code-layout)。

Codex 使用 app-server 读取历史和精确查询线程。Claude 使用 hooks 观察到的元数据和 `claude --resume`，不解析内部会话正文。Chrome 路由按需从本地 Codex rollout 中读取选中标签页上下文；rollout 是不稳定格式，标签页上下文不会序列化保存。

## 快照与事件流

```text
提供方会话目录 + 进程快照 → 本地记录 → 启动器初始快照
提供方 hooks / 任务标记 → 原子更新记录 → 文件系统事件 → watch 快照
```

会话目录查询和进程发现只在打开或手动刷新时执行。`watch` 在初始加载前订阅，监听目录以捕获文件的原子替换，并将 50 ms 内的事件合并处理。后续投影不查询提供方、不探测进程，也不回写记录。视图拥有订阅，关闭视图时会停止子进程。没有轮询或自动重连服务。

各提供方的失败相互独立；查询失败时仍可使用缓存元数据，并显示明确警告。Vicinae 还会按二进制路径缓存最近一次成功的会话数组。缓存状态仅供参考，打开会话时会重新验证实际目标。

## 归属与恢复

位置绑定（lease）记录提供方、窗格 / TTY、PID 和进程启动时间。一个运行中的 CLI 可以承载多个线程。`display_state` 将承载关系与当前显示的线程区分为 `current`、`background` 和 `unknown`。只有当前对话标题唯一匹配的会话才会继承窗格的审批提示；匹配时会排除项目名和路径后缀。

从外部重命名 Codex 线程后，已运行的 TUI 可能继续输出旧终端标题。刷新或打开时，会从 `$CODEX_HOME/session_index.jsonl`（`CODEX_HOME` 默认为 `~/.codex`）读取可选的名称历史；这是不稳定的本地格式。
旧名称只能用于已有绑定，要求已验证的 PID、启动时间和 TTY 未变，工作目录匹配，且不存在当前或历史名称相同的竞争会话。旧名称不能用于发现新绑定，也不能恢复已被替换的进程。启动器显示新名称，定位时则重新核对 TUI 实际输出的旧标题。缺少名称历史时，仍保守地只匹配当前标题。历史别名列表不会序列化到 Sesswitch 记录中。

Hooks 只会从经过验证、带有 TTY 的 CLI 祖先进程注册终端位置。守护进程 / GUI hooks 仍可记录元数据和活动，但不会信任继承的窗格环境变量。缺失的位置可以通过唯一的标题 / 工作目录匹配，以及窗格 TTY 上存活的提供方进程发现。

PID 或启动时间变化会使原位置绑定失效。恢复时还要求精确匹配 `codex resume <thread-UUID>` 参数、当前标题 / 工作目录，并确认新进程上没有竞争标题或绑定。系统提供的进程参数仅在恢复时读取（Darwin 使用 sysctl，Linux 使用 procfs），不会保留；读取后还会再次验证进程身份和 TTY。
参数只描述启动时的情况，因此在线程切换后，不能覆盖与之矛盾的当前标题或已有绑定。通过选择器 / `--last` 启动、无法读取参数或存在歧义时，均不进行推断恢复。

## 打开会话

对于经提供方确认、已有缓存的 Codex 线程，自动打开会先协调所有缓存的同级会话，并尝试经过验证、当前显示目标的 tmux 位置；此步骤不依赖 app-server 是否可用。仅由 hooks 记录或无法恢复的会话不会使用这条捷径。
提供方查询使用精确线程读取，并在补全结果时纳入缓存的同级会话。找不到已保存线程，并不必然说明这是一条 `/side` 会话记录。

定位时会验证 PID、启动时间、提供方和 TTY，并重新检查对话标题。优先复用 WezTerm 中已连接的 tmux 客户端，否则连接已有 tmux 会话。位置失效或目标在后台时可以回退到精确恢复；其他激活错误则停止处理，避免启动重复的 AI CLI。
保留的 `host` 字段记录终端来源，但不保证旧位置仍然存活。新启动的 WezTerm GUI 会脱离请求取消、进程组和输出管道的生命周期。

`--target host` 显式定位到承载会话的 CLI，不选择线程。Chrome 优先定位记录的标签页 ID，或唯一且完全匹配的 URL；失败时将 Chrome 置于前台。VS Code 路由目前只会将应用置于前台。

## 状态与持久化

运行状态、任务完成状态和宿主可用性相互独立。Stop hook 表示一轮对话结束。`mark read` 确认已查阅这一轮结果；`mark done` 是显式的任务完成决定。新的非关闭活动会重新打开 Done 任务。关闭浏览器并不会自动确认待查阅提醒（见 issue #6）。

私有 JSON 记录采用 `<provider>--<id>` 文件名，读取时兼容旧版未带提供方前缀的记录。写入采用原子替换；元数据、活动和任务更新共用文件锁。Hook 到达时间会在进程探测前记录，较早的观察和延迟到达的工具事件不能覆盖较新的轮次状态。排序依据是实际观察到的到达时间，不会虚构提供方事件序列。

## 执行环境

`internal/toolenv` 在每条命令中只解析一次工具，并在提供方、宿主和启动器操作之间共享绝对路径、配置和子进程 PATH。npm 安装的 AI CLI 通过选定的 Node 运行。
由于已有 GUI 的环境可能过期，WezTerm 子进程会显式接收工具和配置位置。只有调用 WezTerm 时，才会在继承的 socket 已不存在时移除该设置。
